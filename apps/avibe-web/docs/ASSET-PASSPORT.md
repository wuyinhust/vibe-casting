# AVIBE 数字达人资产护照

## 入口与流程

- 达人详情新增「资产护照」：公开编号、平台登记时间、当前身份／造型版本、分项材料状态、文件指纹及 JSON 摘要。
- 创作者在自己人物的护照中提交说明和证明。支持 PDF、PNG、JPEG、UTF-8 TXT／JSON 原始文件，单文件最多 10 MB。
- 运营后台新增护照管理入口，可选择正式人物或候选账号，查看私密材料、通过、退回或撤回核验。导入候选仍是待核实账号，不自动转成正式人物或获得许可。
- 支持按身份版本或指定造型提交。后续身份版本不会自动继承旧版本的核验；指定造型的记录不适用于其他造型。

## 编号和证据

登记编号形式为 `AVB-P-00000001`，由数据库唯一序列分配，首次登记后稳定保留。允许序列有空号；编号不表示登记顺序之外的权利优先级。候选账号护照明确标注其还没有对应人物资产。

平台收到文件时记录真实接收时间、字节数及 SHA-256。原始证明以原字节保存，下载再次校验；声明的创作日期是独立字段，不能覆盖平台时间。护照号、文件哈希或平台登记均不单独证明原创或权属。

新图像生成请求自动记录模型、实际提示词、尺寸／质量、参考资产及指纹、模板版本和调用时间；成功返回记录可取得的请求编号、用量和原始输出指纹。模拟提供方明确标记为 injected-provider。旧任务仅展示此前已保存的数据，不补造生产历史。模型 API 未配置时不会产生真实生成记录。

## 审核与许可

分项登记：创作过程、主体身份、权利来源、展示、素材分发、改编／换装、商业内容、品牌合作、再许可、外部作品登记。外部登记的机构、编号、对应作品及核验经过可写入该类型的材料说明并附证明文件；尚无官方登记接口或自动验真服务。

提交记录不会授予权限。运营核验必须附至少一份证明文件并填写审核意见；审核使用修订号防止并发覆盖。支持有效期、尚未生效、已到期、退回和撤回，保留操作记录。审核通过的公开摘要才展示给访客；摘要不得包含合同秘密或个人信息。

护照审核与现有角色包许可、单用户授权分开。审核不会自动发布人物、修改商业许可开关或发放下载权限；撤回核验也不自动解除既有合同，需运营按合同另行处理资产可见性和下载授权。

## 私密范围

证明文件、声明人、私密说明、生产提示词、任务详情及审核意见只允许人物本人和运营访问；候选账号仅运营可见。个人 Skill 令牌不能读取这些私密数据。证明附件必须经过服务端会话鉴权，即使知道附件编号也不能绕过权限。所有新表启用 RLS 并撤销匿名／普通登录角色的直连权限；正式环境仍需 Supabase 实测。

## 角色包与 Skill

新生成的完整角色包包含 `ASSET-PASSPORT.json`，记录编号、身份版本、造型和在线查询路径，列入 manifest 的文件大小及哈希校验。已经发布的旧包不重写，仍可从人物详情查询实时护照。登记快照不是额外许可；实际使用需查看 LICENSE.json 和有效协议。

- `GET /api/v1/passports/characters/:id?identity_version=1&look_id=...`：符合可见性条件的公开摘要；本人或运营网站会话获得私密扩展。
- `GET /api/v1/passports/leads/:id`：运营专用候选档案。
- `POST /api/v1/passports/{characters|leads}/:id/evidence`：上传证明。
- `POST /api/v1/passports/{characters|leads}/:id/claims`：提交材料。
- `GET /api/v1/passports/evidence/:id`：鉴权下载原始证明。
- `GET /api/v1/admin/passports`、`POST /api/v1/admin/passports/review`：运营目录与审核。

## 部署和边界

升级执行 `004_asset_passports.sql`，新安装需先执行 001、002、003。本地 PGlite 启动自动执行可重复迁移；正式数据库使用部署迁移。现有人物与候选账号已登记本地编号；新对象首次查看护照或首次生成／出包时登记，不回填虚假的历史登记时间。

这是平台资产登记与证据管理功能，不是国家版权登记、官方确权或法律保证。当前未接入第三方可信时间戳、公证、区块链存证、身份认证机构或电子合同签署服务；数据库记录不是独立第三方存证。
